# G3.5 可靠性、故障注入与本地性能基线

## 1. 能保证什么

G3.5 保护的是本地学习核心和未来平台适配边界：重复请求不能重复计分，同一幂等键不能偷换
正文，模型或存储故障不能产生半条学习记录，模型不可用时确定性诊断仍能完成。

它不是公网生产方案。当前 API 只绑定回环地址，没有 TLS、鉴权、限流、分布式状态或真实平台
压测。本页的延迟来自本机 ASGI 内存传输，不能写成互联网 SLA 或真实用户效果。

## 2. 幂等请求指纹

每个新诊断回执保存两个哈希：

- `submission_key`：有外部幂等键时由“匿名档案 + 幂等键”生成；无外部键时就是内容指纹；
- `request_fingerprint`：由匿名档案、题目、答案、思考过程、Python 文本和提示层级确定性生成。

完全相同的正文可以更换 `request_id` 或会话标识后安全重试。相同幂等键配不同正文会在首次读取
和最终 SQLite 短事务中各检查一次；即使两个请求并发竞争，也只有一个能创建状态与回执，另一个
得到 409。回执表通过 `ALTER TABLE ... ADD COLUMN` 兼容旧数据库，不删除原有学习记录。

## 3. 可选模型可靠性

| 环境变量 | 默认值 | 代码允许范围 | 含义 |
| --- | ---: | ---: | --- |
| `MODEL_TIMEOUT_SECONDS` | 8 | `>0` 且 `<=120` | 每次模型尝试的硬超时 |
| `MODEL_MAX_ATTEMPTS` | 2 | 1–3 | 一个逻辑解释的总尝试次数 |
| `MODEL_RETRY_BASE_DELAY_SECONDS` | 0.05 | 0–2 | 线性有界等待基数 |
| `MODEL_CIRCUIT_FAILURE_THRESHOLD` | 3 | 1–20 | 连续逻辑失败后开启熔断 |
| `MODEL_CIRCUIT_OPEN_SECONDS` | 30 | `>0` 且 `<=600` | 半开探测前的冷却时间 |

模型返回内容的 Pydantic 校验也在超时/重试边界内。一次成功会清零连续失败；达到阈值后，冷却期
内不再调用模型，健康检查只显示安全的 `degraded`。冷却结束只允许一个半开探测，成功后关闭
熔断，失败则重新计时。熔断只保存在当前 Python 进程中，不伪装成跨机器协调机制。

无论超时、重试耗尽还是熔断，系统都会采用已经生成的确定性报告；分数、证据、掌握度、引用和
推荐不由模型决定。故障日志只保存事件 ID、UTC 时间、组件、稳定代码、异常类型和恢复动作。

## 4. API 客户端重试规则

`BoundedApiRetryPolicy` 不发送网络请求，只给未来平台客户端一个确定性决定：

1. 总尝试次数最多 3 次；
2. 只处理错误体中 `retryable=true` 的 500/503；
3. POST 必须携带并复用原来的幂等键；
4. 409、422 和其他非重试错误立即停止；
5. 等待采用有上限的指数退避，不能无限循环。

服务端不会在客户端失败后猜测是否重试。调用方超时后仍应使用同一个幂等键；如果第一次实际上
已经提交成功，重放会直接返回原报告而不再次更新掌握度。

## 5. 故障矩阵

| 注入 | 期望结果 |
| --- | --- |
| 相同键、相同正文 | 200 重放，历史仍 1 条 |
| 相同键、更改正文 | 409，不返回旧报告，不写新状态 |
| 第一次诊断服务异常 | 503；客户端同键第二次成功，历史 1 条 |
| SQLite 回执插入失败 | 503；状态与回执一并回滚，历史 0 条 |
| 模型每次超时 | 每个逻辑调用最多 2 次尝试，返回本地报告 |
| 连续两次逻辑超时（演示阈值） | 熔断开启；第三次不调用模型，仍返回本地报告 |
| 离线无 Key | 从不调用模型，完整确定性闭环可用 |

## 6. 本地性能门槛与复现

验收脚本对 24 个隔离匿名档案，以并发上限 6 调用完整 `/v1/diagnose`。每个档案必须恰有 1 条
学习历史，成功率必须为 100%，本机 P95 门槛为 3,000 ms。门槛来自早期适配计划中的本地工具
API 目标，故意留出共享机器负载余量；它不是公网 SLA。

```bash
.venv/bin/python scripts/g3_reliability_demo.py \
  --output docs/competition/g3_5_reliability_result.json
```

机器可读结果同时记录 Python 版本、操作系统、CPU 架构、逻辑 CPU 数、P50、P95、最大延迟和
所有故障结果。脚本使用 HTTPX ASGI 内存传输、临时 SQLite 和合成模型函数，不访问互联网、ADP
或真实模型，也不执行学习者 Python 文本。
