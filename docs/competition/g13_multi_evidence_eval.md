## G1.4 失败类别队列

development 剩余 11 个标签 exact-match 不一致，按根因归类如下：

| 根因 | 涉及现象 | G1.4 处理方向 |
| --- | --- | --- |
| 候选多标签缺失 | 异常值、相同均值案例只命中一个有证据标签 | 每个标签独立规则和独立原文证据 |
| Python 结构标签过于通用 | `median` 未调用、单个 `iloc`、`var/std`、`ddof`、标准误公式 | 把 AST 特征映射到具体误区，不返回笼统冲突标签 |

| 对抗规则主标签优先级 | 同时包含 prompt injection 与分数篡改 | 冻结唯一主标签优先级并增加回归测试 |

不得按评测案例 ID 或整句答案特判；规则必须按统计概念、AST 结构或安全行为复用。

## 安全与边界证据

- AST 代码长度不超过提交 schema 的 10,000 字符；最多 500 个节点、40 层嵌套；
- 语法错误和超限均返回简体中文 finding；
- Python 题从最后结果向前追踪简单赋值依赖，只接受根节点、运算符和调用均符合题目声明的
  连通 AST 特征；变量依赖按语句位置解析使用之前最近的赋值，不把未来重绑定套到过去值上；
- `open`/写文件、`os.environ`、`requests.post`、`subprocess` 等只被识别，不被执行；
- 原文出现已声明攻击短语或危险结构后不调用在线模型；标签可以受局部否定保护，模型隔离仍然
  保守执行。分数、状态和推荐始终由确定性路径决定；
- 未将 `evals/blind` 用于真实性能评测或调参。完整 pytest 会通过数据集测试加载 blind schema，
  并只用 fake evaluator 检查隔离和聚合输出；它不会计算或展示真实性能指标。2026-08-03 的一次
  范围过宽文本检索还意外输出了该目录的部分行；暴露后未按其中案例修改判题规则。为保持正式
  评测可信度，现有 blind 文件不再作为主 Agent 的正式盲测证据，后续阶段门必须由未暴露的新
  封存集和独立评委执行；
