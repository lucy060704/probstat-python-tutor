## 关键设计决定

1. **深度单元与细粒度知识点分开。** 8 个单元使用 `DeepUnitId`，避免把单元数量直接套入
   “每知识点三题”规则而错误膨胀题量。
2. **题库允许加分题。** 每个已发布知识点从“正好三题”改为“至少三题且覆盖三类题型”，
   描述统计单元可保留现有 6 题，后续也能扩展到 28–32 题。
3. **提示 0–4 有明确含义。** 0 表示未使用；1–3 逐步引导；4 才显示结构化完整解释。
   第四级使用四个 Pydantic 字段，不能用一段自由文本假装覆盖四维。
4. **新 Python 题必须交代码。** `python_code_required=true`；只有目标列的
   `isna()/isnull()` 零参数调用后紧接零参数 `sum()` 才通过。简单赋值回溯允许，散落调用、
   错误列、`eq(0)`、`fillna(0)`、缺括号和额外参数均拒绝。
5. **旧学习状态可迁移。** 已有 4 个知识点分数原样保留，新增 `data_quality` 使用中性初值
   0.5，不要求用户删除本地 SQLite。
6. **目录映射只是目标。** 章级 `coverage_level` 不代表已经实现或审核；单元真实状态和教师
   核对状态分别由 `content_status`、`verification_status` 表示。
