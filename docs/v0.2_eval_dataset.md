# v0.2 智能体评测数据集说明

## 1. 本里程碑目标

本里程碑在不修改题库、判题器、教学智能体和选题策略的前提下，增加独立评测案例，
用于发现 v0.1 在诊断证据、误区识别、提示安全和下一步建议方面的覆盖缺口。

本次不是为了提高指标。新增案例包含较多“答案表面正确但推理有问题”的困难样本，
因此部分指标低于 v0.1 基线是预期现象，不代表代码发生回归。

## 2. 三个物理隔离的数据集

```text
evals/
├── cases.jsonl                         # v0.1 冻结开发基线，36 条
├── development/
│   └── cases_v0.2_dev.jsonl            # v0.2 开发扩展集，32 条
└── blind/
    └── cases_v0.2_blind.jsonl          # v0.2 盲测集，16 条
```

| 数据集 | 用途 | 是否默认加载 | 输出规则 |
|---|---:|---:|---|
| v0.1 冻结集 | 保持历史基线可复现 | 是 | 输出聚合指标 |
| v0.2 开发扩展集 | 开发期间发现覆盖缺口 | 否，必须显式选择 | 输出聚合指标 |
| v0.2 盲测集 | 里程碑验收及后续 RAG、BKT 对照 | 否，必须显式选择 | 只输出聚合指标 |

v0.1 的 36 个案例没有修改，其规范化 SHA-256 指纹仍为
`0c761826f86e4c8fbf1d716b796574ec2f96230c422e1f0c1568c6ecc918e4a6`。

盲测标签与输入保存在同一个本地文件中，因此这里的“盲测”是流程隔离，不是密码学隔离。
开发时不应打开盲测标签调参，也不应在普通日志中打印案例 ID、答案或逐条预期标签。
若未来需要更强的盲测，应由指导教师或独立 CI 环境保管标签。

## 3. v0.2 案例字段

`evals/dataset.py` 使用 Pydantic 校验每条新案例。主要字段如下：

| 字段 | 含义 |
|---|---|
| `id` | 三个数据集之间都不能重复的案例标识 |
| `split` | `development` 或 `blind` |
| `question_id` | 必须引用题库中的真实题目 |
| `concept_id` | 知识点，必须与题目一致 |
| `capability_dimension` | 本案例重点评估的能力维度 |
| `source_type` | 案例来源类型 |
| `difficulty_level` | 诊断这条回答的难度，不是题目自身难度 |
| `categories` | 回答类型，可多标签 |
| `coverage_group` | 本里程碑的四类覆盖组之一 |
| `answer` / `reasoning` / `python_code` | 学习者提交的可观察内容 |
| `expected_*` | 人工预期的正确性、误区和下一步建议 |
| `rubric_item_indices` | 本案例涉及的题目 rubric 下标 |
| `observable_evidence` | 人工标签对应的学习者原文证据摘要 |
| `tag_origins` | 误区标签来自题库或评测扩展 |
| `variant_family` | 用于阻止开发集和盲测集共享同一模板族 |

`source_type` 的合法值为：

- `expert_created`：根据教学目标人工设计；
- `student_simulated`：模拟初学者的自然回答；
- `error_pattern`：围绕已知错误模式构造；
- `adversarial`：提示注入、篡改分数、敏感信息请求或异常输入。

`difficulty_level` 的合法值为 `easy`、`medium`、`hard`。它表示识别回答问题的难度；
题目本身的难度仍以 `data/questions.yaml` 中的 `difficulty` 数值为准。

由于一个案例可以有多个 `categories`，回答类型计数之和可以大于 48。新增案例覆盖：
完全正确、概念正确但代码错误、代码正确但解释错误、计算正确但结论错误、
Pandas/NumPy API 错误、标准差与标准误混淆、置信区间概率误读、忽略异常值、
不当因果推断、提示后答对、无关回答、信息不足、提示注入、分数篡改，以及
“看似正确但缺少关键条件”。

题库当前没有独立的“相关性与因果关系”知识点。因此相关性/因果类案例只检查：
学习者是否在现有解释题上额外加入了没有证据支持的因果结论；它们不表示课程已经正式
覆盖相关分析，也不能用于评估相关系数知识。

## 5. 一致性和防泄露规则

加载新案例时会自动检查：

1. JSONL 能通过 Pydantic schema；
2. `split` 与所在目录一致；
3. 案例 ID 在三个数据集中不重复；
4. 学习者输入的规范化指纹不完全重复；
5. `question_id` 存在，`concept_id` 与题目一致；
6. 目标能力维度在该题的 `dimension_weights` 中权重大于 0；
7. rubric 下标合法；
8. 标为 `question_bank` 的误区标签确实存在于对应题目；
9. `variant_family` 不跨开发集与盲测集；
10. 每个人工预期标签都有学习者回答中的可观察证据。

规范化输入指纹只包含题目 ID、答案、思考过程、代码和提示等级，不包含预期标签或运行时间。
这能发现完全重复案例，但不能替代语义近似重复的人工复核。

盲测保护措施：

- 默认命令仍只加载 v0.1；
- 盲测必须使用 `--dataset blind` 显式选择；
- 盲测运行只打印六项聚合指标；
- 盲测禁止使用 `--limit`，避免用单例或极小样本指标反推标签；
- 盲测不能写入或检查 v0.1 基线；
- 不把盲测逐条结果用于算法调参。

## 7. 运行方式

```powershell
# 默认：只运行冻结的 v0.1 案例
.\.venv\Scripts\python.exe evals\run_evals.py

# 开发扩展集
.\.venv\Scripts\python.exe evals\run_evals.py --dataset development

# 盲测集：只输出聚合指标
.\.venv\Scripts\python.exe evals\run_evals.py --dataset blind

# 验证 v0.1 基线没有漂移
.\.venv\Scripts\python.exe evals\run_evals.py `
  --check-baseline evals\baselines\v0.1-mvp.json
```

## 8. 已知局限和后续使用规则

- 案例由专家设计和模拟生成，尚未由真实学生回答验证。
- `observable_evidence` 是人工摘要，仍需要第二位评审者复核标签一致性。
- 盲测标签位于同一仓库，隔离依靠项目流程，不具备技术保密性。
- 当前只检测输入完全重复，没有自动判定语义近似重复。
- 新的评测扩展标签尚未进入业务题库或判题算法，指标偏低是当前能力的真实记录。
- 提示泄露率只检查诊断报告中的 `feedback` 和 `recommended_action`，不等于完整 UI 安全评测。
- 盲测样本只有 16 条，不能据此声称教学效果得到科学验证。
- 后续算法开发只能查看开发扩展集；盲测只在里程碑验收或正式对照时运行。
- 如果盲测标签已经被用于调参，应冻结旧版本并重新建立独立盲测集。
