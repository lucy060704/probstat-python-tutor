# 概率统计 × Python 数据分析学习诊断智能体：产品规格（v0.1）

## 文档信息

- 产品版本：v0.1
- 文档状态：里程碑 1，可作为后续设计与验收基线
- 用户界面语言：简体中文
- 实现边界：本文件只定义产品行为与数据契约，不包含业务代码

设计决定与理由：先冻结一个小版本的范围、流程和数据结构，再开始编码。这样可以减少初学项目中常见的“边写边改目标”，并让每个后续里程碑都有明确的验收依据。

## 1. 产品目标

本产品面向概率统计与 Python 数据分析的初学者，提供一个可解释、可诊断、可持续练习的单智能体学习应用。它需要帮助学习者完成以下闭环：

1. 回答一道范围明确的题目；
2. 获得确定性的正确性判断；
3. 在需要时逐层获取提示，而不是立即看到答案；
4. 理解统计概念、数学计算、Python 实现和数据解释之间的联系；
5. 查看基于作答证据生成的能力画像；
6. 获得适合当前薄弱点的下一题推荐。

产品的核心价值不是替代教材或给出更多答案，而是发现学习者“具体卡在哪里”，并提供下一步可执行的学习行动。

设计决定与理由：将“确定性判题”和“大模型解释”分开。分数、掌握度和推荐所依赖的事实由可测试的程序产生；大模型只负责把已有事实解释得更自然。这样即使模型不可用，学习主流程仍然可靠。

## 2. 目标学习者

主要学习者同时具备以下特征：

- Python 初级：理解变量、列表、函数等基础语法，但对 NumPy、Pandas 和统计计算不熟悉；
- 概率统计初级：接触过均值、方差等术语，但容易混淆定义、公式和解释；
- 大模型应用开发初级：可能不知道 API Key、提示词、结构化输出和确定性工具之间的关系；
- 软件工程初级：需要清晰的运行命令、错误信息、测试示例和小步迭代过程；
- 使用简体中文学习，希望代码标识符保留常见英文写法。

不要求学习者具备微积分、统计推断的严格证明能力或前端工程经验。

设计决定与理由：用“入门但不是零基础”作为默认水平，可以从真实数据与短代码切入，同时避免把 v0.1 扩展成 Python 语法课程或数学证明课程。简体中文用于交互，英文用于代码标识符，以便学习者逐步适应真实 Python 生态。

## 3. v0.1 范围

### 3.1 知识范围

v0.1 只覆盖四个主题，每个主题内置 3 道题，共 12 道：

| 主题 | 题目数 | 最低覆盖内容 |
| --- | ---: | --- |
| 均值与中位数 | 3 | 基本计算、异常值影响、选择合适统计量 |
| 方差与标准差 | 3 | 离散程度、总体与样本口径、结果解释 |
| 抽样与标准误 | 3 | 总体与样本、抽样波动、标准误与样本量 |
| 置信区间 | 3 | 区间构造、置信水平解释、区间宽度影响因素 |

### 3.2 产品能力范围

v0.1 包含：

- 一个单智能体式学习体验，不包含智能体之间的协作；
- 12 道版本化内置题；
- 数值题、选择题、文本分类题和安全的 Python 理解题；
- 每道题的标准答案、容差规则、评分规则或固定测试用例；
- 四级渐进提示；
- 确定性判题；
- 四维掌握度更新与本地保存；
- 基于薄弱维度、先修关系和做题历史的下一题推荐；
- 可展示、可追溯到具体作答证据的诊断报告；
- 可选的大模型中文解释；
- 无 OpenAI API Key 时可运行的核心离线流程；
- 所有核心业务逻辑的 pytest 测试。

设计决定与理由：12 道题采用“四个主题 × 每个主题三题”的均衡结构。它足以验证完整闭环，又不会让第一版陷入大规模内容生产。题型允许多样化，但所有正确性都必须能由确定性规则判断。

## 4. 明确排除的功能

v0.1 不包含：

- 多智能体、角色智能体、智能体路由或智能体辩论；
- 四个指定主题之外的概率统计课程；
- 自由运行学习者提交的 Python 代码；
- 在线代码沙箱、Notebook 执行环境或自动安装学习者指定的包；
- 自动生成后直接入库、且未经人工审查的新题；
- 语音、图片识别、视频课程和实时课堂；
- 教师后台、班级管理、排行榜和社交功能；
- 用户注册、云端同步、多设备同步或生产级数据库；
- 支付、订阅和商业化功能；
- 对学习能力、考试成绩或未来表现作高风险预测；
- 严格的统计学证明和高级推断方法。

设计决定与理由：主动排除多智能体、任意代码执行和云端账户系统，因为它们会显著增加调试、安全与隐私成本，却不是验证教学闭环所必需的。v0.1 优先证明“题目—判题—诊断—推荐”能可靠工作。

## 5. 一次完整学习流程

一次完整流程定义如下：

1. **进入应用**：学习者使用随机生成的本地匿名标识开始或恢复学习，不要求提供姓名、邮箱等个人信息。
2. **选择起点**：首次使用时进入短诊断；已有记录时可继续推荐题，也可手动选择四个主题之一。
3. **展示题目**：界面一次只展示一道题，并说明该题要求完成的是概念判断、计算、Python 理解还是数据解释。
4. **提交回答**：系统验证输入格式，然后由确定性评分器判题。
5. **形成证据**：系统记录回答、判定结果、错误类型、使用过的提示和对应题目测试结果。
6. **渐进提示**：回答错误时先提供第一级提示。学习者可以再次尝试或主动请求下一层提示；完整解释只在第四层出现。
7. **更新掌握度**：系统按照题目维度权重、正确性、尝试次数和提示使用情况更新四维掌握度。大模型不能直接修改分数。
8. **解释结果**：系统展示确定性反馈；若配置了模型，可让单智能体基于评分证据生成更自然的中文解释。
9. **推荐下一题**：推荐器优先选择薄弱且满足先修条件的题，避免立即重复已经稳定掌握的题。
10. **展示诊断报告**：学习者可查看总体与分主题画像、证据、优势、待改进点以及下一题推荐理由。
11. **保存并退出**：学习状态保存到本地；下次进入时可以恢复。

无 API Key 时，第 1—7 步以及第 9—11 步必须正常运行；第 8 步使用预先编写的确定性反馈模板。

设计决定与理由：把判题放在提示和解释之前，保证后续反馈有客观依据；把掌握度更新放在推荐之前，保证推荐使用最新状态；一次只展示一道题，以降低初学者的认知负担。

## 6. 四维能力画像

每个维度使用 `0.0` 到 `1.0` 的分数。分数只表示当前题库范围内的掌握证据，不代表通用智力或正式考试能力。

| 维度 | 含义 | 可观察证据示例 |
| --- | --- | --- |
| `concept` | 是否理解统计概念、术语、适用条件及区别 | 能区分标准差和标准误；能说明均值为何受异常值影响 |
| `calculation` | 是否能选择公式并正确完成数学计算 | 正确计算中位数、样本标准差或置信区间端点 |
| `python` | 是否能理解或选择正确的 Python 数据分析实现 | 正确选择 Pandas 方法、参数或判断给定代码输出 |
| `interpretation` | 是否能把数值结果放回数据情境中解释 | 不把 95% 置信区间误读为参数有 95% 概率落在区间内 |

画像至少包含两层：

- 全局四维分数：用于快速概览；
- 按主题划分的四维分数：用于定位“在哪个主题的哪个能力维度”存在薄弱点。

每个分数还需要配套：

- `evidence_count`：支持该分数的有效作答数；
- `confidence`：证据充分度，而不是作答正确率；
- `last_updated_at`：最后更新时间；
- `evidence_refs`：关联到学习记录中的证据标识。

初始掌握度使用中性值 `0.5`，初始 `confidence` 为 `0.0`。更新算法必须满足：正确且少用提示通常上调；错误或高度依赖提示通常下调或小幅上调；单道题不能让维度从最低直接跳到最高；较新的证据权重可以高于较旧证据。具体公式在实现里固定并由测试锁定。

设计决定与理由：四维分离能避免用一个总分掩盖不同困难。例如学习者可能会计算，却不能解释结果。额外记录证据数量和充分度，是为了避免把“只做对一道题的 0.9 分”和“多次稳定做对的 0.9 分”视为同样可靠。

## 7. 分层提示策略

每道题必须提供四层提示，并遵循从少到多的披露顺序：

1. **概念线索（conceptual cue）**：提醒应关注的概念或数据特征，不提供公式和答案；
2. **方法或公式线索（method/formula cue）**：指出合适方法、公式或 Python API 类型，但不代入全部数值；
3. **部分演算步骤（partial worked step）**：完成第一步或关键中间步骤，保留最后的计算或判断给学习者；
4. **完整解释（complete explanation）**：展示完整过程、答案、Python 对应实现以及情境解释。

提示规则：

- 首次展示题目时不展示答案；
- 每次默认只解锁下一层，不跨级自动显示；
- 学习者可以主动请求下一层；
- 每次使用提示都写入学习记录；
- 提示会影响掌握度更新，但不把“使用提示”简单等同于失败；
- 第四层出现后，该次尝试仍被记录，但不能标记为“独立完成”；
- 无大模型时使用题库中人工审核过的固定提示；有大模型时也不能改变提示层级对应的答案披露边界。

设计决定与理由：固定四层结构可以保持教学行为一致，也容易测试。提示使用情况进入评分证据，是为了区分独立掌握和在帮助下完成；但不直接判为失败，是因为合理使用提示本身就是学习过程的一部分。

## 8. 题目数据结构

题目使用版本化、可验证的结构化数据。以下是逻辑结构；后续实现时使用 Pydantic 模型校验。

```json
{
  "id": "mean_median_001",
  "version": 1,
  "topic": "mean_median",
  "title_zh": "异常值对均值的影响",
  "prompt_zh": "给定数据……",
  "response_type": "numeric",
  "difficulty": 1,
  "prerequisite_question_ids": [],
  "dimension_weights": {
    "concept": 0.3,
    "calculation": 0.5,
    "python": 0.0,
    "interpretation": 0.2
  },
  "grading": {
    "strategy": "numeric_tolerance",
    "expected": 12.5,
    "absolute_tolerance": 0.001,
    "accepted_options": [],
    "test_cases": []
  },
  "hints": [
    {"level": 1, "kind": "conceptual", "content_zh": "……"},
    {"level": 2, "kind": "method", "content_zh": "……"},
    {"level": 3, "kind": "partial_step", "content_zh": "……"},
    {"level": 4, "kind": "complete", "content_zh": "……"}
  ],
  "feedback": {
    "correct_zh": "……",
    "common_errors": [
      {"code": "USED_MEAN_INSTEAD_OF_MEDIAN", "message_zh": "……"}
    ]
  },
  "tags": ["outlier", "robustness"]
}
```

字段约束：

- `id` 在题库中唯一，修改题意或答案时增加 `version`；
- `topic` 只能是 `mean_median`、`variance_std`、`sampling_se`、`confidence_interval`；
- `response_type` 只能是预定义安全类型，例如 `numeric`、`single_choice`、`short_text_classification`、`python_output`；
- `difficulty` 在 v0.1 中取 1—3；
- 四个 `dimension_weights` 之和必须为 `1.0`；
- `grading.strategy` 必须对应一个确定性评分器；
- 每道题必须有明确答案、容差规则、选项集合或固定测试用例；
- `hints` 必须正好包含 1—4 级且顺序完整；
- Python 题只判断输出、选择安全代码片段或使用受信任的固定测试，不执行学习者提交的任意代码。

设计决定与理由：题目内容、评分配置和提示放在同一版本化实体中，便于审查一道题是否完整。维度权重允许一题贡献多个能力维度，但总和固定为 1，防止掌握度更新出现隐含权重。Python 题采用安全题型，是为了在没有代码沙箱时彻底避免任意代码执行。

## 9. 学习记录数据结构

学习记录是追加式的事实记录，用于恢复状态、解释评分和生成诊断证据。后续实现时使用 Pydantic 校验，并在 v0.1 中保存为本地结构化文件。

```json
{
  "record_id": "rec_01J...",
  "learner_id": "local_anon_01J...",
  "session_id": "session_01J...",
  "question_id": "mean_median_001",
  "question_version": 1,
  "started_at": "2026-07-11T10:00:00+08:00",
  "completed_at": "2026-07-11T10:03:00+08:00",
  "attempts": [
    {
      "attempt_number": 1,
      "response": {"type": "numeric", "value": 10.0},
      "submitted_at": "2026-07-11T10:01:00+08:00",
      "is_correct": false,
      "score": 0.0,
      "error_codes": ["USED_MEAN_INSTEAD_OF_MEDIAN"],
      "grader_evidence": ["expected=12.5", "received=10.0"]
    }
  ],
  "hints_used": [1],
  "completion_status": "completed_with_hint",
  "mastery_before": {
    "concept": 0.5,
    "calculation": 0.5,
    "python": 0.5,
    "interpretation": 0.5
  },
  "mastery_after": {
    "concept": 0.47,
    "calculation": 0.43,
    "python": 0.5,
    "interpretation": 0.48
  },
  "mastery_update_reason": "首次回答错误；使用一级提示；证据来自 attempt 1",
  "schema_version": 1
}
```

记录规则：

- `learner_id` 默认使用本地匿名标识，不存姓名、邮箱或 API Key；
- 原始回答仅保存在本地，并允许学习者清除；
- 每次尝试保留独立判题证据，不覆盖历史尝试；
- 掌握度更新必须同时保存更新前、更新后和原因；
- 时间使用带时区的 ISO 8601 格式；
- 数据结构带 `schema_version`，为未来迁移留出空间；
- 文件写入需要避免部分写入导致记录损坏，具体原子写入策略留给实现阶段决定。

设计决定与理由：采用追加式记录，而不是只保存最新分数，是为了让每次诊断都能追溯到真实作答。保存掌握度前后快照和更新原因，可以发现算法错误，也能向学习者解释分数为何变化。

## 10. 诊断报告数据结构

诊断报告是某一时间点的派生结果，可以根据题目和学习记录重新生成。分数、证据和推荐由确定性逻辑产生；可选大模型只能改写解释文本。

```json
{
  "report_id": "report_01J...",
  "learner_id": "local_anon_01J...",
  "generated_at": "2026-07-11T10:05:00+08:00",
  "report_version": 1,
  "profile": {
    "overall": {
      "concept": {"score": 0.62, "confidence": 0.5, "evidence_count": 4},
      "calculation": {"score": 0.48, "confidence": 0.5, "evidence_count": 4},
      "python": {"score": 0.55, "confidence": 0.25, "evidence_count": 2},
      "interpretation": {"score": 0.41, "confidence": 0.5, "evidence_count": 4}
    },
    "by_topic": {}
  },
  "strengths": [
    {
      "dimension": "concept",
      "statement_zh": "能够区分均值和中位数的基本含义。",
      "evidence_refs": ["rec_01J...:attempt:1"]
    }
  ],
  "learning_gaps": [
    {
      "dimension": "interpretation",
      "topic": "confidence_interval",
      "statement_zh": "对 95% 置信水平存在概率式误读。",
      "evidence_refs": ["rec_02J...:attempt:1"],
      "error_codes": ["CI_PARAMETER_PROBABILITY_MISREAD"]
    }
  ],
  "recommendation": {
    "next_question_id": "confidence_interval_002",
    "reason_zh": "当前最薄弱且证据较明确的是置信区间的数据解释；该题的先修题已经完成。",
    "target_dimensions": ["interpretation"],
    "candidate_question_ids": ["confidence_interval_002"]
  },
  "data_summary": {
    "questions_attempted": 4,
    "questions_completed": 3,
    "records_used": ["rec_01J...", "rec_02J..."]
  }
}
```

报告规则：

- 每项优势和薄弱点必须包含至少一个 `evidence_ref`；
- 报告明确区分 `score` 与 `confidence`；
- 数据不足时显示“证据不足”，不能编造结论；
- 下一题推荐必须包含目标维度和可读理由；
- 相同题库版本、学习记录和算法版本应产生相同的分数与推荐；
- 大模型生成的说明不得新增记录中不存在的分数、错误或学习者特征。

设计决定与理由：把报告定义为可重建的派生数据，可以在算法修复后重新生成，而不篡改历史学习记录。强制证据引用落实“诊断必须来自可观察回答”，也能约束大模型避免凭印象评价学习者。

## 11. 功能验收标准

v0.1 只有同时满足以下标准才算完成。

### 11.1 题库与教学内容

- 内置恰好 12 道首发题，四个主题各 3 道；后续小版本可以增加题目；
- 每道题都通过题目数据结构校验；
- 每道题都有明确答案、数值容差、可接受选项或固定测试用例；
- 每道题都有四级渐进提示；
- 第一级提示不直接泄露最终答案；
- 题目整体能够覆盖 `concept`、`calculation`、`python`、`interpretation` 四个维度。

### 11.2 判题与掌握度

- 支持题库中声明的所有题型和确定性评分策略；
- 对相同输入重复判题得到相同结果；
- 错误输入得到简体中文提示，不导致应用崩溃；
- 能保存并恢复学习者的全局及分主题四维掌握度；
- 掌握度更新只使用评分器结果、题目权重、尝试次数和提示记录；
- 大模型不能直接创建或修改正确性、分数和掌握度。

### 11.3 报告与推荐

- 能展示全局四维画像及分主题画像；
- 每条诊断结论都能定位到具体学习记录和作答证据；
- 数据不足的维度明确标注证据不足；
- 能推荐一道人选有效、未被稳定掌握且满足先修条件的下一题；
- 推荐结果包含目标维度和推荐理由；
- 所有题已稳定掌握时，系统给出复习建议，而不是返回无效题目。

### 11.4 离线与测试

- 没有 OpenAI API Key 时，题目浏览、确定性判题、提示、掌握度更新、记录保存、诊断报告和下一题推荐仍能运行；
- 没有 API Key 时使用固定中文反馈，不显示堆栈错误；
- 所有核心逻辑都有 pytest 测试，至少覆盖正常情况、边界情况和错误输入；
- 测试不得依赖真实 OpenAI API，也不得产生模型调用费用；
- 相关 pytest 测试全部通过；
- README 或等效文档提供可复制的本地演示命令。

设计决定与理由：“无 API Key 仍可运行”被提升为验收条件，而不是降级建议，因为判题、掌握度和推荐属于产品核心能力。测试覆盖边界与错误输入，是为了确保产品不仅能演示成功路径，也能安全处理初学者常见输入错误。

## 12. 隐私与代码执行风险

### 12.1 隐私风险与控制

主要风险包括原始回答泄露、API Key 泄露、日志意外记录个人信息，以及本地学习记录被其他用户读取。

v0.1 必须采用以下控制：

- 默认不收集姓名、邮箱、电话号码、学校、精确位置等身份信息；
- 使用随机本地匿名 `learner_id`；
- 学习记录默认仅保存在本机，并提供明确的存储位置说明与清除方式；
- `.env`、API Key、令牌和本地学习数据不得提交到 Git；
- 日志不得输出 API Key 或完整环境变量；
- 向大模型发送内容前进行最小化，只发送完成解释所需的题目、回答和确定性判题结果；
- 无模型功能时，不应有任何学习数据离开本机；
- 诊断报告避免使用“能力差”“没有天赋”等人格化或高风险标签。

### 12.2 代码执行风险与控制

学习者提交的 Python 代码可能读取文件、窃取密钥、访问网络、无限循环、耗尽内存或修改系统。因此 v0.1：

- 不使用 `eval()` 或 `exec()`；
- 不在 Streamlit 主进程或任何应用进程中运行学习者提交的任意代码；
- Python 能力题只采用选择题、预测输出、填空式受限答案或对受信任固定代码运行预定义测试；
- 不接受由学习者指定的导入、文件路径、Shell 命令或依赖安装；
- 对所有文本和数值输入设置类型、长度、范围与格式限制；
- 将来若增加自由代码执行，必须作为独立版本设计，并使用隔离沙箱、资源限制、网络限制和超时机制；该能力不属于 v0.1。

设计决定与理由：v0.1 完全不运行任意学习者代码，是最容易验证且风险最低的边界。仅过滤危险字符串并不能构成可靠沙箱，因此不采用“黑名单过滤后执行”的方案。隐私上坚持最小收集原则，可以减少本地应用不必要的数据责任。

## 设计决定汇总

为便于后续实现时快速检查，本规格的关键决定如下：

1. 第一版只做单智能体和四个统计主题；
2. 首发题库固定为 12 道，每个主题 3 道；
3. 正确性、分数、掌握度和推荐均由确定性逻辑决定；
4. 大模型是可选解释层，不是核心判题依赖；
5. 能力画像拆成概念、计算、Python、解释四维，并区分分数与证据充分度；
6. 所有诊断结论必须引用具体作答证据；
7. 提示严格按四层逐步披露；
8. 题目、学习记录和诊断报告都采用版本化结构化数据，并计划用 Pydantic 校验；
9. v0.1 本地匿名保存学习状态，不建设账户和云同步；
10. v0.1 不运行任意学习者代码；
11. 无 API Key 时完整核心流程仍可用；
12. 所有核心逻辑必须经过不依赖真实模型的 pytest 测试。
